# UI Evidence

ユーザー可視のサーフェスを変更する PR では、現在のエージェントが変更前後の証跡を取得し、PR コメントとして投稿する。レビュアーは証跡を生成しない。

## 対象

- 差分がユーザー可視の UI（画面、テンプレート、CSS、文言、操作フロー）を変更する場合。
- リポジトリの指示が証跡を要求する場合。
- 判断できない場合は、証跡なしと決めつけず、ユーザーに一度だけ確認する。
- 証跡が不要と判断した場合は、その理由を完了報告に残す。

## 取得

- [Playwright](../../playwright/SKILL.md) を使い、変更前と変更後の状態、または完了状態を最小枚数で撮る。
- 時間経過に依存する主張だけ動画を使う。動画が 10 MB を超える場合はスクリーンショットへフォールバックし、その理由を記録する。
- 成果物は `PW_ARTIFACT_DIR` などの一時ディレクトリに置き、リポジトリへコミットしない。

## 投稿

- PR 本文には入れない。head ごとの PR コメントにする。
- コメントの先頭に head を示すマーカーを付ける。マーカーのプレフィックスは既存コメントの識別子であり、スキルディレクトリが改名されても変更しない。

  `<!-- pi-pr-review-workflow:ui-evidence head=<head SHA> -->`

- 画像は alt 付きのインライン参照 `![<what it shows>](<absolute path>)` とし、同じパスを `attachments` に `<absolute path>#<what it shows>` として入れる。
- 動画は単独の段落 `![](<absolute path>)` にし、タイムラインを添える。動画には alt テキストを付けない。
- すべての添付を本文から参照する。参照しない添付は gh CLI が末尾に追加し、投稿後の検証を判定不能にする。
- 同じ head のコメントを再利用できるのは、本文が今回の全項目をすでに列挙している場合だけ。項目が増えたら新しいコメントを作る（`comments.update` では添付を追加できない）。
- 修正 push が UI を変える場合は、その head の証跡を追加する。変えない場合は前回の証跡を再利用し、その旨を報告する。
- 投稿は [GH](../../gh/SKILL.md) の `comments.create` と明示的な `grant: "write"` を使う。投稿後にコメント ID/URL と本文を確認する。
