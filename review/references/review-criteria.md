# Review Criteria

## ラベル

各指摘の先頭には次のラベルを一つだけ使う。Blocker は影響の大きさだけでなく、マージを止めて修正すべきかで判定する。

- **Blocker**: マージ前に修正が必要な不具合、仕様違反、セキュリティ問題、データ破壊、主要機能の停止。
- **Nit**: タイポ、表記、機械的に直せる軽微な問題。
- **Consider**: 設計や保守性についての検討提案。対応、別 Issue 化、見送りは担当者が判断する。
- **FYI**: 対応を求めない参考情報。

## 品質ゲート

次のすべてを根拠付きで説明できる候補だけを投稿する。

1. 差分によって導入または悪化する一つの問題である。
2. 入力、状態、権限、順序、環境などの発生条件を具体化できる。
3. 差分、関連コード、テスト、一次資料のいずれかが根拠になる。
4. 呼び出し元、ガード、型、設定、仕様、テストで反証されていない。
5. 原因から問題となる挙動と利用者、データ、運用、後続処理、変更容易性への影響を追える。
6. 確認した範囲を超えて一般化せず、ラベルに見合う確度がある。

反証済み、判断不能、差分と無関係、好みだけ、到達条件のない仮説、要約や称賛だけの候補は投稿しない。同じ原因と失敗条件を持つ候補は一つにまとめる。
