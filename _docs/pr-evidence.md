# PR body evidence

ユーザー可視のサーフェスを変更する PR、またはリポジトリが証跡を要求する PR では、Before/After の証跡を PR 本文の証跡節に載せる。証跡コメントは使わない。レビュアーは証跡を生成しない。

## 対象

- 差分がユーザー可視の UI（画面、テンプレート、CSS、文言、操作フロー）を変更する場合。
- リポジトリの指示が証跡を要求する場合。
- 判断できない場合は、証跡なしと決めつけず、ユーザーに一度だけ確認する。
- 証跡が不要と判断した場合は、その理由を完了報告に残し、本文に証跡節を作らない。

## 取得

- [Playwright の証跡手順](../playwright/references/evidence.md) に従い、変更前と変更後の状態、または完了状態を最小枚数で撮る。
- Before/After の静止画には、変更箇所の印を付ける。After だけを撮る場合も、変更箇所に印を付ける。
- 時間経過に依存する主張だけ動画を使う。動画が 10 MB を超える場合はスクリーンショットへフォールバックし、その理由を記録する。
- 成果物は `PW_ARTIFACT_DIR` などの一時ディレクトリに置き、リポジトリへコミットしない。

## 節の形式

本文の次のブロックを証跡節とする。開始マーカーの `head` は、その証跡が対象とする head の完全な SHA にする。

````markdown
<!-- pi:ui-evidence:start head=<head SHA> -->

## 証跡

| 変更前（入口なし） | 変更後（行メニュー） |
| --- | --- |
| ![変更前: 非ワークツリーの行。右端にメニューがない](<absolute path>) | ![変更後: 同じ行の右端に「…」がある](<absolute path>) |

- 対象: 非ワークツリーの `scratch` 帯、390px。
- 対象 head: `<head SHA>`。UI 変更なしで再利用する場合は、再利用元の head も書く。
- 補足: 選択・既読はメニューを開いただけでは変わらない。

<!-- pi:ui-evidence:end -->
````

- 見出しは本文の言語に合わせる（例: `## 証跡`、`## UI Evidence`）。マーカーは言語に依存させない。
- 比較する静止画は、1 行 2 列までのパイプテーブルにまとめる。ヘッダには何を比べているかを書く。3 列以上にしない。3 枚以上は 2 列で折り返す。
- テーブルのセルには Markdown の画像参照を置き、`width` を指定しない。GitHub は表を本文幅に収め、画像を自動で縮小する。
- テーブルに入れない単独画像は、通常の Markdown 画像参照のままにする。表示サイズを変える必要がある場合だけ、アップロード済み URL を `src` にした `<img width="<px>">` を使う。`width` は PNG の実寸以下にし、拡大しない。
- 動画は単独の段落 `![](<absolute path>)` にしてプレイヤーとしてレンダリングし、その下にタイムラインを置く。動画には alt テキストを付けない。
- alt はヘッダに頼らず、各画像に何を写したか書く。
- モバイルでは 2 列テーブルの各セルが 130px 程度まで縮む。読めない場合は、テーブルではなく同じ段落に画像を空白区切りで並べ、幅が足りないときに折り返させる。列ラベルは付けられないため、前後の文脈で何の画像か分かる場合だけ使う。
- 節の位置は `Verification` の直後、`Rollout` の前を優先する。見出しがない場合は本文の末尾に置く。位置よりマーカーの一意性を優先する。
- 本文には証跡節を 1 つだけ置く。開始マーカーが複数ある、または開始と終了が対応しない場合は、更新せず停止する。
- マーカーのない既存の証跡見出しがある場合は、重複する節を作らず、その見出しの下をマーカー付きの節に置き換える。判断できない場合は停止する。

## 作成と更新

- すべての添付を本文から参照する。本文が参照しないファイルは gh CLI が末尾に追加し、書き込み後の検証を判定不能にする。
- `pr.create` または `pr.update` の `attachments` に、本文と同じローカルパスのリテラルを入れる。画像は `![<what it shows>](<absolute path>)`、同じパスを `<absolute path>#<what it shows>` として添付する。
- 既存 PR の本文を更新するときは、更新直前に `pr.read` で本文を読み、開始マーカーと終了マーカーの間だけを差し替える。マーカーがなければ節を挿入する。それ以外の本文は変更しない。
- 修正 push で UI が変わらない場合は、画像を再アップロードせず、開始マーカーの `head` を最新 head に更新し、節に「UI 変更なしのため、head=<以前の head> の証跡を再利用」と書く。
- 修正 push で UI が変わる場合は、新しい画像で節を差し替える。古い画像は本文から外す。
- `<img width>` を使う場合は、まず Markdown 参照で `pr.create` または `pr.update` して返却 body の URL を得る。次にその URL を `src` に入れて `pr.update` する。2 回目は添付を追加せず、マーカーと他の本文を変えない。
- 作成・更新は [GH](../gh/SKILL.md) の `pr.create` / `pr.update` と明示的な `grant: "write"` を使う。
- `unknown_outcome` は不明として扱い、`pr.read` で本文と head を再確認する。確定できない場合は自動リトライせず停止する。
- 作成・更新後に `pr.read` で、開始マーカーの `head` が現在 head と一致し、参照した画像 URL が本文に残り、ローカルパスが残っていないことを確認する。

## 完了ゲート

UI 変更またはリポジトリが証跡を要求する PR では、Ready または完了の前に `pr.read` で次を確認する。

- 本文に証跡節が 1 つだけある。
- 開始マーカーの `head` が現在の PR head と一致する。
- pass とした各項目に、その項目を証明する画像または動画の参照がある。
- 本文にローカルの添付パスが残っていない。

確認できない場合は成功として扱わず、Draft のまま停止する。
