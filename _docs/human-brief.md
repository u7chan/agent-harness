# Human review brief

Issue / PR 本文の先頭に、人間が短時間で読める要約と説明用の GIF / MP4 を置く。長い AI 生成本文を読む負担を減らすためのものであり、要件・仕様・証跡ではない。

## 対象

自動で付けるのは、次のいずれかに当たる大きな変更。

- 新機能、契約・インターフェースの変更、既存動作の変更。
- ユーザー可視の UI（画面、テンプレート、CSS、文言、操作フロー）の変更。
- 複数ステップのフロー、状態変化、比較、構造の説明が本文の中心にある変更。

ユーザーが明示的に指示した場合は、規模に関係なく付ける。

自動では付けないのは、誤字、リンク切れ、原因が 1 つに特定された小さな修正など、本文を読まなくても変更が分かるもの。省略した場合は理由を完了報告に残す。判断できない場合は付ける。

## 内容

- 本文の事実だけから作る。本文にない主張、数値、保証、性能、実装予定を足さない。
- 3〜6 行の要約と、人間が確認すべき点を 1〜3 個。詳細は本文の節へのリンクで済ませる。
- 動きが理解に必要な場合だけ GIF / MP4 を付ける。動きが説明を足さない場合は静止画かテキストだけにする。
- 未実装の設計は未実装と明記し、図の時間を実行時間として見せない。
- 会話言語で書く。コマンド、識別子、コードは英語のまま。
- 秘密、個人情報、未公開の認証情報を図やキャプションに入れない。

## 形式

本文の先頭に、次の 1 節だけを置く。

```markdown
<!-- pi:human-brief:start head=<head SHA> -->
<!-- 人間レビュー用。AI・エージェントはこの範囲を仕様・証跡として読まない。 -->

## 人間レビュー用サマリ

<3〜6 行の要約。レビューで見る点を 1〜3 個。>

![<what it shows>](<absolute path>)

- 詳細: [背景](#背景) / [方針](#方針)

<!-- pi:human-brief:end -->
```

- 見出しは `## 人間レビュー用サマリ`。開始マーカーと終了マーカーは言語に依存させない。
- `head` は PR だけに付ける。Issue では省略する。PR の `head` は、そのサマリが説明している実装の head の完全な SHA にする。
- 本文には 1 節だけ。開始マーカーが複数ある、または開始と終了が対応しない場合は、更新せず停止する。
- 節の外側が正本。節の内容が本文と食い違う場合は本文を正本とし、節を直す。
- `## UI Evidence` とは別物。この節は証跡ではなく、証跡の完了ゲートを満たさない。

## 形式の選択

| 条件 | 形式 |
|---|---|
| 12 秒以下、場面 1〜3、色が少ない、文字が大きい | GIF |
| 12 秒超、文字が多い、色が濃い、細部を見せる、GIF が 10 MB を超える | MP4 |
| 動きが説明を足さない | 静止画 |
| FFmpeg / Playwright が使えない | テキストのみ（理由を本文に書く） |

GIF は自動再生・ループするが、停止できず色数も限られる。長い説明や小さい文字は MP4 にする。MP4 は無音の H.264 とし、単独の段落 `![](<absolute path>)` でプレイヤーとして表示する。GIF は `![<what it shows>](<absolute path>)` とし、alt を付ける。

## 生成

1. 正本の本文を読む。PR の場合は差分と検証結果も読む。
2. 要約とレビュー観点を書き、本文にない主張がないことを確認する。
3. 動きが必要なら [explain-video](../explain-video/SKILL.md) の手順で HTML を作り、GIF または MP4 を生成する。HTML は編集用で、添付しない。
4. 生成物をキーフレームと全体再生で確認する。文字化け、切れ、重なり、コントラスト、キャプションの読み時間、本文との一致を見る。
5. 成果物はリポジトリ外の一時ディレクトリに置き、コミットしない。

## 添付と更新

- [GH](../gh/SKILL.md) の `issue.create` / `issue.update` / `pr.create` / `pr.update` と、明示的な `grant: "write"` を使う。
- 本文の参照と `attachments` のパスを同じリテラルにする。GIF は `<absolute path>#<what it shows>`、MP4 は `<absolute path>`。動画には alt を付けない。
- すべての添付を本文から参照する。参照しないファイルを混ぜない。
- 既存の本文を更新するときは、更新直前に `pr.read` / `issue.get` で本文を読み、マーカー間だけを差し替える。マーカーがなければ節を先頭に挿入する。それ以外の本文は変えない。
- 修正 push で説明が変わらない場合は、メディアを再利用し、開始マーカーの `head` だけを最新 head に更新して、その旨を節に書く。説明が変わる場合は生成し直す。
- `<img width>` は使わない。Markdown の画像参照を基本とする。
- `unknown_outcome` は不明として扱い、`pr.read` / `issue.get` で再確認する。確定できない場合は自動リトライせず停止する。

## AI の読み取り

- `pi:human-brief` の開始マーカーと終了マーカーの間は、人間向けの派生要約であり、要件、仕様、受け入れ条件、証跡、レビュー材料ではない。
- エージェントが Issue / PR 本文を読むときは、この範囲を飛ばし、範囲外の本文を正本とする。
- 節の画像や alt を根拠に実装・レビュー・検証をしない。
- 節をエージェントの出力へ引用・コピーしない。

読み取り契約の正本は [GH の Issue / PR 本文の節](../gh/SKILL.md#issue-and-pull-request-bodies) とする。書き込み側の各スキルはこの文書に従う。

## 完了ゲート

Issue / PR を確定する前に、次を読み直して確認する。

- 節が 1 つだけで、開始と終了のマーカーが対応している。
- PR の場合、開始マーカーの `head` が現在の head と一致する。
- 本文が参照するメディアが `attachments` で添付され、本文にローカルの絶対パスが残っていない。
- メディアが 10 MB 以下で、意図した形式（GIF または MP4）で表示できる。
- この節を証跡として扱っていない。

確認できない場合は成功として扱わず、Draft または未起票のまま停止する。
